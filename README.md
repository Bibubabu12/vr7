# depgraph-apt

Инструмент визуализации графа зависимостей пакетов Ubuntu (apt).
Зависимости получаются собственным кодом из индекса `Packages`
репозитория, без `apt`, `dpkg` и сторонних библиотек.

## Состояние

Этапы 1-5: параметры из командной строки; сбор прямых зависимостей
пакета из индекса `Packages` (форматы: обычный, `.gz`, `.xz`);
построение графа транзитивных зависимостей рекурсивным DFS;
порядок загрузки (`--order`);
визуализация в Graphviz (DOT) и PNG.

## Параметры командной строки

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `-p`, `--package` | имя анализируемого пакета | обязательна |
| `-r`, `--repo` | URL индекса репозитория или путь к файлу тестового репозитория | обязательна |
| `-t`, `--test-mode` | режим тестового репозитория: `--repo` — путь к файлу | выключен |
| `-o`, `--output` | имя файла с изображением графа (`.png`) | `graph.png` |
| `-d`, `--max-depth` | максимальная глубина анализа (целое, >= 0) | `3` |
| `--order` | вывести порядок загрузки зависимостей вместо графа | выключен |

Ошибки в параметрах приводят к сообщению `error: ...` в stderr и коду
возврата `1`.

## Сборка и тесты

Сборка не требуется (чистый Python 3.9+, только стандартная библиотека).

```
make test
```

## Примеры

```
make run ARGS="-p curl -r https://archive.ubuntu.com/ubuntu/dists/jammy/main/binary-amd64/Packages.gz -d 2"
make run ARGS="-p curl -r http://x -d -1"
```

## Как собираются зависимости

* Индекс репозитория скачивается по URL (`urllib`) и разбирается
  собственным парсером формата `Packages` (абзацы `Поле: значение`).
* Прямые зависимости — поля `Pre-Depends` и `Depends`.
* Из версионных ограничений, архитектур (`:any`, `[amd64]`) остаются
  только имена пакетов.
* Для альтернатив `a | b` выбирается первая, найденная в индексе.
* Виртуальные пакеты (`Provides`) заменяются первым пакетом-поставщиком.
* Зависимость, которой нет в индексе, считается листом графа.

```
make run ARGS="-p curl -r https://archive.ubuntu.com/ubuntu/dists/jammy/main/binary-amd64/Packages.gz"
make run ARGS="-p app -r file://$PWD/tests/data/Packages.sample"
```

`tests/data/Packages.sample` — небольшой синтетический индекс для тестов.

## Граф зависимостей (этап 3)

Граф строится рекурсивным обходом в глубину (`graph.build_graph`).

* Корень имеет глубину 0. Пакеты на глубине `--max-depth` попадают в граф,
  но их зависимости не раскрываются.
* Если пакет сначала встретился слишком глубоко, а потом найден по более
  короткому пути, он раскрывается повторно, поэтому результат не зависит
  от порядка обхода.
* Циклы не приводят к зацикливанию: обратное ребро запоминается и
  выводится строкой `cycle: X -> Y`.
* Слишком большая глубина (превышение лимита рекурсии Python) даёт
  понятную ошибку `error: max depth ... is too large for recursive DFS`.

Вывод: рёбра `A -> B`, пакеты без зависимостей — отдельной строкой.

## Тестовый режим

С флагом `-t` опция `-r` — путь к файлу с описанием графа. Строка
`A: B C` означает «A зависит от B и C». Имена — заглавные латинские
буквы, `#` начинает комментарий. Готовые файлы лежат в `examples/`.

```
make run ARGS="-t -p A -r examples/chain.txt -d 3"
make run ARGS="-t -p A -r examples/diamond.txt -d 3"
make run ARGS="-t -p A -r examples/cycle.txt -d 5"
make run ARGS="-t -p A -r examples/shortcut.txt -d 3"
```

| Файл | Что демонстрирует |
|------|-------------------|
| `chain.txt` | цепочка и ограничение глубины |
| `diamond.txt` | общая зависимость (ромб), без дублей |
| `cycle.txt` | циклические зависимости |
| `shortcut.txt` | повторное раскрытие по более короткому пути |
| `large.txt` | граф побольше, с циклом через `M -> A` |

## Порядок загрузки (этап 4)

`--order` печатает пакеты в порядке, в котором их нужно загружать:
зависимости идут раньше зависящих от них пакетов, корень — последний.
Используется обход в глубину с выводом при выходе из вершины
(`order.load_order`); в цикле пакет, достигнутый первым, загружается
последним.

```
make run ARGS="-t -p A -r examples/chain.txt -d 5 --order"     # D C B A
make run ARGS="-t -p A -r examples/diamond.txt -d 5 --order"   # D B C A
make run ARGS="-t -p A -r examples/cycle.txt -d 5 --order"     # C B A
make run ARGS="-t -p A -r examples/large.txt -d 10 --order"
```

### Сравнение с реальным менеджером пакетов

Сравнение выполняется на Ubuntu (например, в контейнере
`ubuntu:22.04`), для того же индекса, что передан в `--repo`:

```
apt-get update
apt-get install -s --no-install-recommends curl | grep -E '^(Inst|Conf)'
make run ARGS="-p curl -r <URL Packages.gz> -d 100 --order"
```

Ожидаемые расхождения (их нужно проверить и зафиксировать по факту
запуска):

* `apt` не выводит уже установленные пакеты, а инструмент выводит все
  транзитивные зависимости;
* `apt` учитывает версионные ограничения и политику выбора версий и
  альтернатив; инструмент берёт первую найденную альтернативу и первую
  версию из индекса;
* порядок внутри независимых ветвей может различаться: общим является
  только требование «зависимость раньше зависимого»;
* циклы `apt` разрывает по своим правилам (`Pre-Depends` важнее
  `Depends`), инструмент — на первом повторно достигнутом пакете;
* `--max-depth` усекает граф, а `apt` всегда берёт его целиком.

## Визуализация (этап 5)

Без `--order` инструмент формирует описание графа на языке Graphviz,
выводит его на экран (stdout) и сохраняет изображение в PNG-файл,
имя которого задано в `--output`. Корневой пакет выделен рамкой и
заливкой, рёбра, замыкающие цикл, — красные. Сообщение о сохранении
файла выводится в stderr.

Для создания изображения нужен установленный Graphviz (команда `dot`):
`sudo apt install graphviz`. Если `dot` не найден, выводится понятная
ошибка, а описание DOT остаётся в stdout и его можно отрисовать вручную.

```
make run ARGS="-t -p A -r examples/cycle.txt -d 5 -o cycle.png"
make run ARGS="-p curl -r <URL Packages.gz> -d 2 -o curl.png"
make run ARGS="-p python3 -r <URL Packages.gz> -d 2 -o python3.png"
make run ARGS="-p nginx -r <URL Packages.gz> -d 2 -o nginx.png"
```

`<URL Packages.gz>` — например,
`https://archive.ubuntu.com/ubuntu/dists/jammy/main/binary-amd64/Packages.gz`
(для пакетов из `universe` нужен индекс `universe`).
Файлы `examples/*.dot` — готовое DOT-описание тестовых графов:
`dot -Tpng examples/cycle.dot -o cycle.png`.
PNG-файлы в репозиторий не добавляются (см. `.gitignore`).

### Сравнение со штатным инструментом

Штатное средство визуализации для apt — `apt-cache dotty`:

```
apt-cache dotty curl | dot -Tpng -o curl_apt.png
```

Ожидаемые расхождения (проверяются по факту запуска): `apt-cache`
строит граф по всем указанным в индексе альтернативам и версиям,
без ограничения глубины, а инструмент — по первой найденной альтернативе
и только до `--max-depth`; оформление узлов и рёбер тоже отличается.

## Проверка стиля репозитория

`tests/test_style.py` автоматически проверяет правила рецензирования:
длину строк (<= 80), размер файлов (< 1000 строк) и функций (<= 40),
число аргументов (<= 7), цикломатическую сложность (<= 10), отсутствие
комментариев вместо docstring и числовых литералов в сравнениях.
